Profile Real-Time Preview

The Profile Real-Time Preview view draws the profile you are editing as a UML class diagram, and redraws it each time you save. As well as showing the profile's structure, it marks definitions that are incomplete or invalid, so you can see and fix problems while you build the profile rather than when a schema is generated. It always follows the profile in the active Profile Editor.

When the Diagram Is Redrawn

  • When you save the profile. Your zoom level and position are kept, so you can watch one part of a large diagram while you work on it.
  • When you switch to another profile's editor. The new profile is drawn fitted to the view, with the current diagram style for that profile.
  • When you change the diagram preferences (see Colors and What the Diagram Includes) and click Apply or Apply and Close.

The preview does not depend on the builders selected on the Profile Summary tab: it is drawn for every profile, whether or not the profile generates any PlantUML artifact.

Diagram Style and Your Profile's Target

The preview is drawn by one of the PlantUML builders, chosen by the Diagram Style setting. Use a style that matches your profile's target, because the builders for each target lay out the profile differently and check different rules (see How Problems Are Shown). Top-to-bottom or left-to-right is a matter of taste and changes only the layout.

Diagram StyleProfile targetLayout
puml-rdfs-t2bRDFSTop to bottom (the default)
puml-rdfs-l2rRDFSLeft to right
puml-xsd-t2bXSDTop to bottom
puml-xsd-l2rXSDLeft to right
puml-json-t2bJSON SchemaTop to bottom
puml-json-l2rJSON SchemaLeft to right

The Diagram Style list shows every PlantUML builder available in CIMTool, including any you have imported, so it can contain more than these six.

The style can be set at three levels, and CIMTool uses the most specific one that is set:

LevelWhere to set itApplies to
ProfileRight-click the profile (.owl) in the Project Explorer, choose Properties, then CIMTool, and set Diagram Style.That profile only.
ProjectRight-click the project, choose Properties, then CIMTool, and set Diagram Style under Profile Real-Time Preview PlantUML Diagram Preferences.Every profile in the project that does not set its own style.
GlobalWindow > Preferences > CIMTool > PlantUML Builder Preferences, Diagram Style under Profile Real-Time Preview PlantUML Diagram Preferences.Every profile whose project and profile settings are empty.

Leave the profile or project setting empty to use the next level up. A project's profiles usually share one target, so set the style once for the project, and set a profile's own style only when it targets something different. See The Profile Real-Time Preview and Your Target.

Colors and What the Diagram Includes

The preview uses the same diagram preferences as the PlantUML builders: Window > Preferences > CIMTool > PlantUML Builder Preferences. They set the PlantUML theme, the color for each kind of class (document root, concrete and abstract classes, enumerations, CIMDatatypes, compounds, primitives, choices, references and shadow classes), dark mode and shadowing, and whether enumerations, CIMDatatypes, compounds and primitives are drawn at all.

Hiding a kind of class does not hide a problem with it: a hidden enumeration or compound that a definition refers to incorrectly is still drawn in the preview, so that the problem stays visible.

A class can have more than one parent class, for example when the schema was imported with During import merge shadow/mixin extensions into the CIM classes that inherit from them cleared, so that a shadow class stays a second parent of the class it extends. The diagram then draws an inheritance arrow to each parent, for every target.

How Problems Are Shown

The preview marks a problem by drawing the class concerned in pink, by drawing an association line in red, or by attaching a pink note. Which problems are reported depends on the diagram style, so the style must match your profile's target. Each problem below names the profile targets it applies to.

What you seeWhat it meansTargetsHow to fix it
A pink class or enumeration with no members, at the end of an association or attributeA definition in the profile refers to a class or type that is not in the profile.RDFS, XSD and JSON SchemaAdd the class or type to the profile on the Add/Remove tab, or remove the definition that refers to it.
A red line from a class to an enumeration, compound or datatypeAn attribute of that type is in the profile, but its type was not selected in the attribute's definition. Attributes are drawn as members of the class, never as lines, once their type is selected.RDFS, XSD and JSON SchemaOn the Add/Remove tab, select the class, then the attribute in the profile pane, and move its type from the schema pane to the profile pane. Save.
A red association line to a class that is in the profileThe association is in the profile, but its target end was not selected in the association's definition.RDFS, XSD and JSON SchemaOn the Add/Remove tab, select the class, then the association, and move the target class to the profile pane. Save.
A pink note on an attribute: The declared type for this attribute is currently undefined. This should be fixed within either the model and/or profile where required.The attribute has no type, usually because its type is missing in the UML model.RDFS, XSD and JSON SchemaCorrect the attribute's type in the UML model and re-import the schema, or remove the attribute from the profile.
A pink class with the note Class X is 'concrete' but has no fields or associations declared…A concrete class with no attributes, no associations and no parent class: it carries nothing.RDFS onlyOn the Restriction tab, either clear Make this class concrete (if it only refers to an object defined elsewhere) or choose a parent class; or add attributes or associations on the Add/Remove tab.
A pink class with the note Class X is 'abstract' and has no parent class, child class, or association references to it…An abstract class that nothing connects to the rest of the profile, so it can never be used.RDFS onlyMake it concrete on the Restriction tab, or remove it on the Add/Remove tab.
A pink class with the note Class X is 'abstract' and has no child classes…An abstract class with a parent but no concrete class below it, so no object of it can exist.RDFS onlyMake it concrete, add a concrete child class, or remove it.
A pink class with the note Class X is 'abstract'. If it is serving as a reference to an external object then no fields should be defined in it…An abstract class that associations refer to and that has attributes. An abstract class referred to in this way stands for an object defined elsewhere and should carry no attributes.RDFS onlyRemove its attributes on the Add/Remove tab, or make it concrete on the Restriction tab if it is meant to carry data.

The four class notes apply only to RDFS profiles because they follow the RDFS rules for concrete and abstract classes (IEC 61970-501). XSD and JSON Schema profiles are not checked for them.

Profile Real-Time Preview and PlantUML Svg

The CIMTool perspective has a second diagram view beside the preview, PlantUML Svg, which comes from the PlantUML plug-in included with CIMTool. It draws any PlantUML (.puml) file you open or select, such as the diagram a PlantUML builder generates for a profile. It does not follow the active profile and does not mark problems. Use the Profile Real-Time Preview while you design a profile, and PlantUML Svg to look at generated diagrams. To see both at once, drag one view's tab to another part of the window.

Using a Second Monitor

A large profile is easier to read with more space. Drag the Profile Real-Time Preview tab outside the workbench window to detach it into a window of its own, then move it to a second monitor and maximize it. To put it back, either:

  • drag the tab back onto the workbench, or
  • in the CIMTool perspective, choose Window > Perspective > Reset Perspective.... This puts the view back in its default place, but also returns every other view in the perspective to its default layout. In other perspectives, where the view is not part of the default layout, Reset closes it instead.

Putting a detached view back: drag the tab, not the window

To re-attach a detached view, drag its tab, not the title bar of its window. Dragging the title bar only moves the window and never docks it. Hold the tab and drag it over the CIMTool window. Before you let go, Eclipse shows where the view will go: an outline over a group of tabs, or a thin double vertical line running the height of the window for a column of its own. The detached window closes when its last tab leaves it.

If you detached several views, put them back one at a time; each tab is dragged on its own.

Double-clicking the tab, or Ctrl+M, maximizes it inside the workbench instead.
