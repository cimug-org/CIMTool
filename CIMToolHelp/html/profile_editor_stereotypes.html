Stereotypes Tab

The Stereotypes tab applies stereotypes to the element selected in the Outline view. A stereotype tells the builders to treat the element in a particular way when they generate schemas and documentation from the profile.

[Screenshot: the Stereotypes tab with a class selected, showing the checklist of stereotypes.]

Applying Stereotypes

The tab shows "Select stereotypes to apply to this element:" above a checklist of the stereotypes available to the profile. Check a stereotype to apply it to the selected element, or clear it to remove it. The change is made in the profile straight away and saved when you save the profile.

The list combines three sources:

  • the stereotypes defined in the schema;
  • CIMTool's own stereotypes, such as concrete, Description and By Reference;
  • any stereotypes declared in a .stereotype-extensions file that complements the schema (see below).

Not every stereotype in the list can be changed. Stereotypes that cannot be changed for the selected element are greyed out.

  • Stereotype extensions: stereotypes declared in a .stereotype-extensions file can always be applied to, or removed from, any element in the profile.
  • CIMTool's own stereotypes: these can be changed only where they suit the selected element. Those set automatically from the schema, such as attribute and enumeration, cannot be changed.
  • Other stereotypes from the schema: these are shown for information but can never be changed, because they come from the UML model.

Some stereotypes are also set by other tabs. For example, Make this class concrete and Set concrete class as descriptor on the Restriction tab apply the concrete and Description stereotypes, and By Reference applies the By Reference stereotype. Prefer those controls where they exist, because they also keep related settings consistent, such as clearing the descriptor when a class is made abstract.

Not every stereotype has a meaning for every element or every target. Whether a builder acts on a stereotype depends on the builder; see Profile Targets.

Stereotype Extensions Files

A stereotype extensions file adds stereotypes that do not need to be in the UML model, but are useful for annotating classes, attributes and associations while profiling. Such stereotypes appear in the documentation generated by the AsciiDoctor builders and in the PlantUML diagrams, giving readers a more meaningful view of the profile.

For example, IEC 61970-452 Ed. 3 co-specifies the ShortCircuit and Operation profiles within the Core Equipment profile. Annotating attributes with a ShortCircuit or Operation stereotype while profiling shows which attributes belong to each, both in the generated documentation and in the diagrams.

The file is used with Enterprise Architect project schemas (.eap, .eapx, .qea and .qeax). It has the same name as the schema file, with the extension .stereotype-extensions, and sits beside it:

Schema
├── iec61970cim16v33c_DY_pack_fix_WITH_ENTSO-E_EXTENSIONS.qea
└── iec61970cim16v33c_DY_pack_fix_WITH_ENTSO-E_EXTENSIONS.stereotype-extensions

When the file is in the same folder as the schema file during a schema import or when creating a new project, CIMTool imports it automatically into the project's Schema folder.

Each line maps a stereotype to a free-form description, in the form <stereotype>=<description>. Lines starting with # are comments:

# Stereotypes used when profiling Core Equipment
Operation=Stereotype used to annotate attributes defined as part of the Core Equipment Operations profile.
ShortCircuit=Stereotype used to annotate attributes defined as part of the Core Equipment ShortCircuit profile.

Following UML 2.5, stereotype names are case-insensitive and must not contain spaces. A stereotype may be written as it appears in the UML or in lowercase; CIMTool treats both the same.

The CGMES-CIM16 project on GitHub includes a complete example.
