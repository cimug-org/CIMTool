Profile Summary Tab

The Profile Summary tab covers the profile as a whole: where it is stored, its namespace, which builders generate artifacts from it, and tools for repairing and reorganizing it. Its settings apply whichever element is selected in the Outline view.

[Screenshot: the Profile Summary tab, showing the location, namespace, buttons and builder list.]

Location and Namespace

ItemShows
LocationThe profile file's path in the workspace.
NamespaceThe profile's namespace, used for the names in the schemas generated from it. Edit opens a wizard to change it.

Choosing Builders

"Build the following from this profile:" lists every builder available in the workspace, each shown as Builder for its name and the extension of the file it creates, for example Builder for puml-rdfs-t2b (.rdfs-t2b.puml). Check the builders that should run for this profile. Each time you save the profile, the checked builders regenerate their files in the Profiles folder, next to the profile.

Choose builders that match the profile's target. See How the Builders Reflect the Target for which builders suit an XSD and JSON Schema profile and which suit an RDFS profile.

Manage XSLT Builders... opens the Manage XSLT Transform Builders wizard, where you can change an existing XSLT builder's type or file extension, or delete it. To replace a builder's XSLT completely, reimport it with the Import XSLT Transform Builder wizard.

Reorganize and Repair

Reorganize and Repair opens the Repair and Reorganize wizard. Choose one or more of its options:

OptionEffect
Stereotype all properties as By ReferenceMarks every association in the profile as By Reference.
Stereotype leaf classes as ConcreteMakes concrete every class in the profile that has no subclass in the profile.
Repair and remap profile to schemaMatches the profile to the current schema again, for example after the CIM has changed. See Profile Maintenance.
Reorganise profile per RDFS rulesRestructures the profile to follow the RDFS profiling conventions.
Reorganise profile per RDFS rules but keep profile cardinalities as currently defined in the profileAs above, keeping the cardinalities already set in the profile.
Reorganise profile per RDFS rules but override profile cardinalities with those defined in the canonical schemaAs above, replacing the profile's cardinalities with the schema's.

The reorganize options are for profiles with an RDFS target. Save a copy of the profile, or commit it to version control, before reorganizing, so that you can compare the result.
