
== **CIMToolHelp**

An Eclipse help plugin that provides the integrated HTML documentation for the
CIMTool application, accessible via *Help > Help Contents* within the running
Eclipse workbench, and the context help shown by *F1* and by the CIMTool
Context Help panel.

This project contains no Java source. Its sole purpose is to package and register
the CIMTool user documentation and context help as an Eclipse help contribution.



=== Overview

CIMToolHelp (`au.com.langdale.cimtoole.help`) is a lightweight Eclipse plugin
that contributes to two extension points:

* `org.eclipse.help.toc`, registering `toc.xml` as the table of contents for the
  CIMTool help system.
* `org.eclipse.help.contexts`, registering three context files that map each
  CIMTool view, editor and Profile Editor tab to a short description and links
  into the help pages. These are what *F1* shows, and the first link of each
  context is the page the CIMTool Context Help panel opens.

All content is static XHTML 1.1 stored in the `html/` directory, styled by
`graphic.css`, with every screenshot opening in a full-window image viewer
provided by `viewer.js`. Pages are written to work both in the Help window and
in a narrow help panel beside the editor: the header stays pinned while the page
scrolls, tables fill the column and stack below 360 pixels, and pages never
scroll sideways. The styles include fallbacks for the Internet Explorer engine
that the embedded browser uses on some Windows systems.

The documentation covers the full range of CIMTool user topics, from getting
started and the workbench through the Profile Editor and each of its tabs, the
Profile Real-Time Preview, project and profile documentation, importing EA models,
validation, namespace management, and OWL/RDF concepts.

=== Dependencies on Other Projects

CIMToolHelp has no compile-time or runtime OSGi dependencies on other in-repository
plugins. It declares no `Require-Bundle` entries in its MANIFEST and contains no
Java source. It relies solely on the Eclipse help framework
(`org.eclipse.help.toc` and `org.eclipse.help.contexts` extension points), which
is provided by the Eclipse platform itself.

The context files are registered against the plugins whose parts they describe,
using the `plugin` attribute in `plugin.xml`:

[cols="2,2,4", options="header"]
|===
| File | Registered against | Covers

| `contexts_CIMTool.xml`
| `au.com.langdale.cimtoole`
| CIMTool's own views, the Profile Editor and its tabs, and the CIMTool Search wizard

| `contexts_Navigator.xml`
| `org.eclipse.ui.navigator`
| `common_navigator`, the Project Explorer

| `contexts_Workbench.xml`
| `org.eclipse.ui`
| `missing`, the fallback for parts with no help of their own
|===

The last two replace contexts that `org.eclipse.platform.doc.user` would
otherwise supply. That bundle is not part of the CIMTool product.

`CIMToolProduct` lists this plugin (`au.com.langdale.cimtoole.help`) in
`CIMTool.product` so it is included in the PDE product export and shipped as
part of the CIMTool distribution. `CIMToolProduct/helpData.xml` references this
plugin's `toc.xml` to control the ordering of help books in the Eclipse help
table of contents:

----
<toc id="/au.com.langdale.cimtoole.help/toc.xml"/>
----

=== Updating the Documentation

All documentation is hand-authored XHTML. To add or update a topic:

. Add or edit the page in `html/`. Name new pages in lowercase words joined by
  underscores, and keep images in `html/images/`, named after the page that
  uses them. Lowercase names matter: Windows matches names regardless of case,
  but the packaged plugin JAR, Linux and macOS do not.
. Keep each page well-formed XHTML 1.1, starting from the template the existing
  pages use, because the Eclipse help system's dynamic content works only with
  XHTML. Give every `<h2>` and `<h3>` an `id` so that context help and other
  pages can link to it.
. If adding a new topic, add a `<topic>` entry to `toc.xml` referencing it via
  the `PLUGINS_ROOT/au.com.langdale.cimtoole.help/html/<filename>.html` path,
  under the group it belongs to, and list it in the same place on the CIMTool
  Topics landing page.
. If the page documents a view, editor, tab or dialog, add or update its entry
  in the matching context file. The first link of each entry is the page the
  CIMTool Context Help panel opens for that part. A new part also needs a help
  context id in `CIMToolPlugin`'s `HelpContextIds`, attached to the part.
. Rebuild and re-export the product. No Java compilation is required for
  changes to this plugin alone.

NOTE: The `PLUGINS_ROOT/` prefix in `toc.xml` href values is an Eclipse
help framework convention that resolves to the installed plugins directory at
runtime. Do not use relative paths or absolute file paths in `toc.xml` entries.
The context files use paths relative to this plugin, such as
`html/profile_preview.html`.



=== Relationship to Other Projects

* *CIMToolPlugin* attaches the help context ids to its views and editors
  (`HelpContextIds`), and contains the CIMTool Context Help panel
  (`CIMToolHelpView`), which shows this plugin's pages for the active part.
* *CIMToolProduct* ships this plugin in the CIMTool distribution and orders
  its table of contents through `helpData.xml`.
